## B40.5 payment correction and test-database safety

**Implementation review: consistent with the recorded correction. Test gate:
BLOCKED — local database identity not established.**

Current [ordersController.ts](../apps/api/src/controllers/ordersController.ts)
performs an initial idempotency lookup, then acquires a transaction-scoped
advisory lock for the order/key and repeats the lookup inside the transaction.
Before inserting a new payment it selects the order `FOR UPDATE` and rejects a
missing or cancelled order. Payment insertion and the guarded
`recordOrderCollection` ledger update share the transaction. The
[paymentConcurrency.test.ts](../apps/api/tests/integration/paymentConcurrency.test.ts)
assertions retain the distinct partial-payment scenario and add a same-key
retry scenario that expects one created payment, four deduplicated responses,
and one persisted payment. No weakening of assertions was made in this
milestone.

The test source contains 15 cases. The B40.5 report records the previous
command `npx vitest run tests/integration/paymentConcurrency.test.ts` passing
15/15 against identity-verified local `hospiflow_test`; this is historical
evidence, not a rerun result for B40.6. B40.5 also explicitly says the
unkeyed three-success scenario was not independently reproduced. This report
does not claim that scenario was fixed.

No database-backed tests were run. The shell process had neither
`DATABASE_TEST_URL` nor `DATABASE_URL`; the ignored `.env` files contained
no `DATABASE_TEST_URL` key among the database URL names checked by
metadata-only inspection. The integration test configuration requires
`DATABASE_TEST_URL`, and the helper can truncate the test database. Therefore
the local dedicated database identity was not established and running the
suite would be unsafe. In addition, the test
setup's success message includes the configured test URL; do not expose test
output containing that URL while arranging a safe rerun.

**Required evidence:** the API/test-database owner must provide an authorized,
dedicated local `hospiflow_test` configuration and verify its identity
read-only (`current_database()` and loopback server address) before running:

- From `apps/api`: `npx vitest run tests/integration/paymentConcurrency.test.ts`
- From `apps/api`: `npx vitest run tests/integration/*.security.test.ts`

Capture exact counts and exit statuses without emitting a database URL or
credential.
